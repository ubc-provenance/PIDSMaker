Tasks¶

Every argument of each pipeline task, as accepted in a system's YAML config or on the command line (e.g. --training.lr=0.001).

How to read this page

  • Keys are nested exactly as in the YAML config. On the CLI, join them with dots: training.encoder.dropout → --training.encoder.dropout=0.3.
  • Click the markers to see a description and the allowed values of an argument.
  • Arguments of interchangeable methods (featurization methods, encoders, decoders, objectives, cleaning) are documented on their own pages: Featurization, Encoders, Decoders, Objectives, Cleaning.

Generated content

The argument lists below are generated from TASK_ARGS in pidsmaker/config/config.py by docs/scripts/get_arguments.py. Don't edit them by hand.

Stage 1: Construction¶

Builds the time-window graphs of provenance or network events from the database. The raw data can be cleaned before the graphs are built with construction.cleaning: see Cleaning.

  • used_method: str (1)
  • use_all_files: bool
  • mimicry_edge_num: int
  • time_window_size: float (2)
  • use_hashed_label: bool (3)
  • fuse_edge: bool (4)
  • consistent_edge_types: bool (5)
  • operations: str (6)
  • drop_noise_events: bool (7)
  • benign_training: bool (8)
  • edge_type: str (9)
  • node_label_features
    • subject: str (10)
    • file: str (11)
    • netflow: str (12)
    • host: str (13)
  • null_label_tokens: bool (14)
  • multi_dataset: str (15)
  • cleaning
    • used_methods: str (16)
  1. The method to build time window graphs.

    Available options (one selection):
    default
    magic
  2. The size of each graph in minutes. The notation should always be float (e.g. 10.0). Supports sizes < 1.0.
  3. Whether to hash the textual features.
  4. Whether to fuse duplicate sequential edges into a single edge.
  5. Map OpTC edge types to DARPA TC equivalents for shared vocabulary across datasets.
  6. Events kept when building graphs, by value of their operation column: default keeps the default events of the dataset's schema (all events, except for OpTC network flows where only FLOW_START events are kept, as in LARES and Argus), all keeps all events, otherwise a comma-separated list of operations (e.g. FLOW_START,FLOW_MESSAGE).
  7. Drops the noise events of the dataset's schema when building graphs (OpTC network flows: NetBIOS, LLMNR and SSDP broadcasts and multicasts and ICMPv6 neighbor discovery, which link every host to most hosts in every time window). No effect on datasets without noise events. Default: True.
  8. Drops the events labelled malicious from the graphs of the train and val dates, so that models are trained and validated on benign events only (datasets with event labels whose train or val dates have attacks). No effect on other datasets and dates. Default: True.
  9. Edge attribute used as edge type by graphs and models (e.g. the type predicted by predict_edge_type). operation is the default type of events of the dataset (e.g. system calls in provenance datasets), other values are categorical edge attributes of the dataset's schema (e.g. logon_type in LANL).

    Available options (one selection):
    auth_type
    dst_port
    dst_user_kind
    logon_type
    operation
    protocol
    src_port
    src_user_kind
    success
  10. Attributes of subject nodes used as node labels (concatenated): path, cmd_line. type adds the node type, and auto uses the type-specific default label, only made of non-null attributes.

    Available options (multi selection):
    auto
    type
    path
    cmd_line
  11. Attributes of file nodes used as node labels (concatenated): path. type adds the node type, and auto uses the type-specific default label, only made of non-null attributes.

    Available options (multi selection):
    auto
    type
    path
  12. Attributes of netflow nodes used as node labels (concatenated): local_ip, local_port, remote_ip, remote_port. type adds the node type, and auto uses the type-specific default label, only made of non-null attributes.

    Available options (multi selection):
    auto
    type
    local_ip
    local_port
    remote_ip
    remote_port
  13. Attributes of host nodes used as node labels (concatenated): name. type adds the node type, and auto uses the type-specific default label, only made of non-null attributes.

    Available options (multi selection):
    auto
    type
    name
  14. When enabled, null entity attributes produce explicit tokens ([NO_CMD], [NO_PATH], [NO_IP]) instead of empty strings.
  15. A comma-separated list of datasets on which training is performed. Evaluation is done only the primary dataset run in CLI.

    Available options (one selection):
    THEIA_E5
    THEIA_E3
    CADETS_E5
    CADETS_E3
    CLEARSCOPE_E5
    CLEARSCOPE_E3
    optc_h201
    optc_h501
    optc_h051
    TRACE_E5
    TRACE_E3
    FIVEDIRECTIONS_E5
    FIVEDIRECTIONS_E3
    PROVENANCE_BENIGN
    ATLASV2_EDR
    CARBANAKV2_EDR
    LANL
    OPTC_NET
    none
  16. Cleaning methods applied to the raw data before building the graphs, or none. remove_null_attributes: null-like attributes (None, NA, <UNNAMED fd:3>, invalid IPs and ports) are removed from labels; normalize_labels: whitespaces, slashes, path prefixes and quotes are normalized and long labels truncated; remove_duplicate_events: events with the same source, destination, type and timestamp are kept once; remove_self_loops: events from a node to itself are removed; remove_noisy_netflows: netflows to multicast/broadcast/... IPs are removed with their events; dedup_window_edges: only the first event of each (source, destination, type) is kept in each time window.

    Available options (multi selection):
    remove_null_attributes
    normalize_labels
    remove_duplicate_events
    remove_self_loops
    remove_noisy_netflows
    dedup_window_edges
    none

Stage 2: Transformation¶

Optional transformations applied to the graphs after construction.

  • used_methods: str (1)
  • rcaid_pseudo_graph
    • use_pruning: bool (2)
    • prune_threshold: float (3)
    • root_node_types: str (4)
    • keep_original_edges: bool (5)
    • merge_same_label_roots: bool (6)
    • max_roots_per_node: int (7)
  • merge_edges
    • per_edge_type: bool (8)
    • aggregate_attributes: bool (9)
  • synthetic_attack_naive
    • num_attacks: int
    • num_malicious_process: int
    • num_unauthorized_file_access: int
    • process_selection_method: str
  1. Applies transformations to graphs after their construction. Multiple transformations can be applied sequentially. Example: used_methods=undirected,dag

    Available options (multi selection):
    undirected
    dag
    rcaid_pseudo_graph
    merge_edges
    none
    synthetic_attack_naive
  2. Whether roots reaching more than prune_threshold of the nodes of the graph get no pseudo edges (R-Caid's pruning of highly-connected roots).
  3. Fraction of the nodes of the graph above which the descendants of a root are pruned (0.5 for DARPA TC in the paper).
  4. Comma-separated node types that can be roots (e.g. file,netflow: files and sockets, as in the paper), or all.
  5. Whether the transformed graph keeps the edges of the provenance graph next to the pseudo edges (root -> descendant), which have no edge type. If False, only the pseudo edges are kept.
  6. Whether the pseudo edges of the roots with the same type and label (thus the same features) towards a same node are merged into one, from the first such root.
  7. Maximum number of pseudo-roots of a node (0: no limit): its roots with the fewest descendants. Bounds the pseudo edges by this number times the number of nodes, e.g. when a process reads thousands of files that become roots of all its descendants.
  8. Whether repeated edges are merged per edge type (one edge per source, destination and type) or regardless of their type (one edge per source and destination, as in Euler). Merged edges have a count and a weight attribute.
  9. Whether the edge attributes of a merged edge (batching.edge_features=edge_attrs) aggregate all its events, as the edge features of Euler, Argus and LARES: the number of events, the number of events with each value of each categorical attribute (e.g. successful and failed logons) and the number, mean and std of the values of numeric attributes, each standardized over the edges of the graph as sigmoid(floor(x / std)). Otherwise, the attributes of the first event are kept.

How node labels are split into tokens before featurization. nltk splits words with NLTK, hierarchical keeps each level of paths and IPs (Kairos), whole_label uses the whole label as a single token (DeepWalk), bpe is the provenance-specific BPE of SPIDER, huggingface uses the tokenizer of a HuggingFace language model, none is for featurization methods that do not tokenize labels.

Feature inference¶

feat_inference runs right after featurization and embeds every node of the graphs with the trained model. Its arguments mostly apply to pretrained encoders: continued pretraining on the target dataset, and the renaming attack.

  • to_remove: bool
  • edge_attributes: str (1)
  • continue_pretrain: bool (2)
  • continue_pretrain_epochs: int (3)
  • continue_pretrain_lr_factor: float (4)
  • edge_batch_size: int (5)
  • rename_attack
    • enabled: bool (6)
    • entities: str (7)
    • target_node_type: str (8)
    • top_k: int (9)
    • target_label: str (10)
    • seed: int (11)
  1. Edge attributes of the dataset's schema used as edge features (batching.edge_features=edge_attrs): all, a comma-separated list of attribute names (names absent from the dataset are ignored), or lists per dataset, e.g. LANL:success;OPTC_NET:src_port,dst_port,protocol (unlisted datasets use all their attributes).
  2. Continue pretraining on the target dataset before inference. Default: False.
  3. Number of epochs for continue-pretraining on target dataset. Default: 3.
  4. LR multiplier relative to original peak LR (e.g., 0.1 = 10x lower). Default: 0.1.
  5. Number of edges to process in each batch during feat_inference. Default: 5000.
  6. If True, after embeddings are computed, replace the embedding of selected test-set nodes with a benign target embedding. Simulates an inference-time renaming/mimicry attack.
  7. Comma-separated BASE NAMES of attack entities (e.g. 'main, XIM, sendmail'). Each is matched two ways against test-set nodes of target_node_type: (a) exact label equality, and (b) labels ending with '/' (path-style).
  8. Node type the attack targets (only nodes of this type are rewritten).

    Available options (one selection):
    subject
    file
    netflow
  9. If >0, automatically build a benign-target pool from the top-K most frequent BARE labels (no '/') of target_node_type seen in the training split, and assign one target per attack entity. Path-suffix matches preserve the original prefix (e.g. '/tmp/main' -> '/tmp/'). If 0, use the manual target_label for every entity (e.g. for an 'unseen-by-pretraining' target).
  10. (Manual mode only, used when top_k=0) Bare base name to replace every attack entity. Path-suffix matches still preserve the prefix (e.g. '/tmp/main' -> '/tmp/').
  11. Seed used to shuffle the auto-picked benign pool before assigning one target per entity. Vary it for sensitivity analysis over which benign label each malicious entity is mimicking.

Stage 4: Batching¶

Selects the node and edge features and builds the batches given to the model. See Batching & sampling.

  • save_on_disk: bool (1)
  • node_features: str (2)
  • edges_distribution_scaling: str (3)
  • edge_features: str (4)
  • multi_dataset_training: bool (5)
  • compact_node_ids: bool (6)
  • fix_buggy_graph_reindexer: bool (7)
  • global_batching
    • used_method: str (8)
    • global_batching_batch_size: int (9)
    • global_batching_batch_size_inference: int (10)
  • intra_graph_batching
    • used_methods: str (11)
    • edges
      • intra_graph_batch_size: int (12)
    • tgn_last_neighbor
      • tgn_neighbor_size: int (13)
      • tgn_neighbor_n_hop: int (14)
      • fix_buggy_orthrus_TGN: bool (15)
      • fix_tgn_neighbor_loader: bool (16)
      • directed: bool (17)
      • insert_neighbors_before: bool (18)
      • reset_state_every_day: bool (19)
      • negative_destinations: bool (20)
  • inter_graph_batching
    • used_method: str (21)
    • inter_graph_batch_size: int (22)
  1. Whether to store the graphs on disk upon building the graphs. Used to avoid re-computation of very complex batching operations that take time. Can take up to 300GB storage for CADETS_E5.
  2. Node features to use during GNN training. node_type is a one-hot encoded entity type vector, node_emb refers to the embedding generated during the featurization task, only_ones is a vector of ones with length node_type, edges_distribution counts emitted and received edges.

    Available options (multi selection):
    node_type
    node_emb
    only_ones
    edges_distribution
  3. Scaling of the edges_distribution counts: max divides them by the largest count of the time window (default), none keeps the raw counts (as ThreaTrace), log1p applies log(1 + x).

    Available options (one selection):
    max
    none
    log1p
  4. Edge features to used during GNN training. edge_type refers to the system call type, edge_type_triplet considers a same edge type as a new type if source or destination node types are different, msg is the message vector used in the TGN, time_encoding encodes temporal order of events with their timestamps in the TGN, edge_attrs are the edge attributes of the dataset's schema besides the edge type (one-hot categorical and log-scaled numeric attributes, e.g. ports or logon types), none uses no features.

    Available options (multi selection):
    edge_type
    edge_type_triplet
    msg
    time_encoding
    edge_attrs
    none
  5. Whether the GNN should be trained on all datasets in multi_dataset.
  6. Renumbers the nodes of the graphs from 0 to (number of nodes in the graphs - 1), keeping their order, instead of using the node IDs of the database, which also count the nodes absent from all graphs (86% of the 44.5M IDs of TRACE_E3). Tensors indexed by node (TGN memory, neighbor loader, node ID embeddings, all_nodes embeddings, ...) are sized accordingly. Node IDs are restored in the outputs. Results are unchanged, except for methods drawing random nodes among all IDs (e.g. uniform negatives of Euler and Argus).
  7. A bug has been found in the first version of the framework, where reindexing graphs in shape (N, d) slightly modify node features. Setting this to true fixes the bug.
  8. Flattens the time window-based graphs into a single large temporal graph and recreate graphs based on the given method. edges creates contiguous graphs of size global_batching_batch_size edges, the same applies for minutes, unique_edge_types builds graphs where each pair of connected nodes share edges with distinct edge types, none uses the default time window-based batching defined in minutes with arg time_window_size.

    Available options (one selection):
    edges
    minutes
    unique_edge_types
    none
  9. Controls the value associated with global_batching.used_method (training+inference).
  10. Controls the value associated with global_batching.used_method (inference only).
  11. Breaks each previously computed graph into even smaller graphs. edges creates contiguous graphs of size intra_graph_batch_size edges (if a graph has 2000 edges and intra_graph_batch_size=1500 creates two graphs: one with 1500 edges, the other with 500 edges), tgn_last_neighbor computes for each graph its associated graph based on the TGN last neighbor loader, namely a new graph where each node is connected with its last tgn_neighbor_size incoming edges. none does not alter any graph.

    Available options (multi selection):
    edges
    tgn_last_neighbor
    none
  12. Controls the value associated with global_batching.used_method.
  13. Number of last neighbors to store for each node.
  14. If greater than one, will also gather the last neighbors of neighbors.
  15. A bug has been in the first version of the framework, where the features of last neighbors not appearing in the input graph have zero node feature vectors. Setting this arg to true includes the features of all nodes in the TGN graph.
  16. We found a minor bug in the original TGN code (https://github.com/pyg-team/pytorch_geometric/issues/10100). This is an unofficial fix.
  17. The original TGN's loader builds graphs in an undirected way. This makes the graphs purely directed.
  18. Whether to insert the edges of the current graph before loading last neighbors.
  19. Empties the last neighbors and resets the TGN memory at the first batch of each day (date of its first event), as Kairos, which trains and tests on one graph per day.
  20. Draws a negative destination for each edge, uniformly among the destinations of the training graphs (training) or of all graphs (validation, test), and adds it to the nodes of the TGN graph to be embedded with memory and neighbors, as TGN and Jbeil (used by predict_edge_contrastive.neg_sampling=tgn).
  21. Batches multiple graphs into a single large one for parallel training. Does not support TGN. graph_batching batches inter_graph_batch_size together, none doesn't batch graphs.

    Available options (one selection):
    graph_batching
    none
  22. Controls the value associated with inter_graph_batching.used_method.

Stage 6: Evaluation¶

Turns the losses into anomaly scores, chooses a threshold and computes the metrics.

  • viz_malicious_nodes: bool (1)
  • ground_truth_version: str (2)
  • evaluate_selected_epoch_only: bool (3)
  • save_figures: bool (4)
  • best_model_selection: str (5)
  • used_method: str
  • node_evaluation
    • threshold_method: str (6)
    • max_val_loss
      • alpha: float (7)
    • use_dst_node_loss: bool (8)
    • use_kmeans: bool (9)
    • kmeans_top_K: int (10)
    • ocrapt_contamination: float (11)
    • ocrapt_min_contamination: float (12)
    • magic_knn_k: int (13)
    • magic_max_reference_size: int (14)
    • magic_embedding: str (15)
  • tw_evaluation
    • threshold_method: str (16)
  • node_tw_evaluation
    • threshold_method: str (17)
    • use_dst_node_loss: bool
    • use_kmeans: bool
    • kmeans_top_K: int
  • queue_evaluation
    • used_method: str (18)
    • queue_threshold: int
    • kairos_idf_queue
      • include_test_set_in_IDF: bool
    • provnet_lof_queue
      • queue_arg: str
  • host_two_stage_evaluation
    • alpha: int (19)
    • beta: int (20)
    • root_attack_nodes: str (21)
    • test_end: str (22)
  • edge_evaluation
    • malicious_edge_selection: str (23)
    • threshold_method: str (24)
  1. Whether to generate images of malicious nodes' neighborhoods (not stable).

  2. Available options (one selection):
    orthrus
    reapr
    threatrace
  3. Only evaluates the epoch selected by a label-free best_model_selection (last_epoch, best_val_score), instead of evaluating every epoch on the test set (faster on large test sets, without per-epoch test metrics).
  4. Whether to save the figures of the evaluation (scores, ADP and discrimination curves) for each evaluated epoch. Metrics are computed either way. Figures with one point per edge or node are slow to draw on large test sets.
  5. Strategy to select the best model across epochs. best_adp selects the best model based on the highest ADP score, best_discrimination selects the model that does the best separation between top-score TPs and top-score FPs. These two use test labels. best_val_score selects the model with the best score on validation data computed by the objective (link prediction AUC + AP of validation edges for predict_edge_contrastive), as Euler's early stopping. last_epoch selects the last evaluated epoch (no labels used). best_mcc selects the best MCC on the test set (as LARES' code).

    Available options (one selection):
    best_adp
    best_discrimination
    best_ap@10
    best_val_score
    best_mcc
    last_epoch
  6. Method to calculate the threshold value used to detect anomalies.

    Available options (one selection):
    max_val_loss
    mean_val_loss
    percentile
    threatrace
    magic
    flash
    nodlink
    fixed_zero
    ocrapt
  7. Weights the margin applied to the threshold value.
  8. Whether to consider the loss of destination nodes when computing the node-level scores (maximum loss of a node).
  9. Whether to cluster nodes after thresholding as done in Orthrus
  10. Number of top-score nodes selected before clustering.
  11. For threshold_method=ocrapt: max per-type contamination (top fraction flagged), clamped from that type's own val malicious fraction.
  12. For threshold_method=ocrapt: min per-type contamination floor.
  13. For threshold_method=magic: number of nearest benign training nodes whose mean distance scores a test node (default 10, as in the MAGIC paper).
  14. For threshold_method=magic: the k-NN reference set is a random sample of at most this many benign training node embeddings (0: all of them).
  15. For threshold_method=magic: node embedding scored by the k-NN detector, the output of the last encoder layer (last, MAGIC's code) or the concatenation of all its layers (concat, MAGIC's paper).

# Installation with Docker

Docker is optional: PIDSMaker [installs with pip](installation.md). The `pids` container is a ready-made environment, with PIDSMaker installed from the repository, a VS Code Dev Container to edit, run and debug the code, and the tools to [build datasets from scratch](from-scratch.md).
{ .lead }

!!! info "Requirements"
    - :fontawesome-brands-linux: **Linux** with [Docker](https://docs.docker.com/engine/install/ubuntu/#install-using-the-repository), ideally with an :simple-nvidia: **NVIDIA GPU**. Avoid running Docker as root: [manage Docker as a non-root user](https://docs.docker.com/engine/install/linux-postinstall/#manage-docker-as-a-non-root-user). Without a GPU, PIDSMaker [falls back to CPU](quickstart.md#gpu-or-cpu).
    - :fontawesome-brands-apple: **macOS** (Apple Silicon) with [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/), on CPU (Docker has no access to Apple GPUs).

## 1. Set up Docker

=== ":fontawesome-brands-linux: Linux + :simple-nvidia: NVIDIA GPU"

    Install the NVIDIA Container Toolkit, so that the containers can use the GPU. Skip this step to run on CPU only.

    ```shell
    # Add the NVIDIA package repository
    curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
    curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
      sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
      sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list

    # Update and install
    sudo apt-get update
    sudo apt-get install -y nvidia-container-toolkit

    # Restart services
    sudo systemctl restart docker
    sudo nvidia-ctk runtime configure --runtime=docker
    sudo systemctl restart docker
    ```

=== ":fontawesome-brands-apple: macOS"

    1. **Give memory to Docker.** The containers run in the virtual machine of Docker Desktop, limited to 8 GB by default. Runs on provenance datasets can take more than 15 GB: give the VM about 75% of your RAM, as explained in [macOS with Docker Desktop](installation.md#docker-desktop).
    2. **Let Docker read the repository.** If the repository is in a protected folder such as `~/Documents` or `~/Desktop`, `docker compose` fails with `mkdir /host_mnt/Users/...: operation not permitted`. Allow Docker in **System Settings > Privacy & Security > Files and Folders** (or **Full Disk Access**), then restart Docker Desktop.

## 2. Configure the paths

Clone the repository, and copy the environment template at its root:

```shell
git clone https://github.com/ubc-provenance/PIDSMaker.git && cd PIDSMaker
cp .env.local .env
```

Then edit `.env`:

| Variable | Description |
|---|---|
| `ARTIFACTS_DIR` | *(optional)* Where all files generated by the pipeline are written (multiple GBs), and the downloaded datasets. Mounted as `/home/artifacts` in the `pids` container. |
| `VIZ_PORT`, `PIDS_PORT` | *(optional)* Host ports of the visualization server (`5000` by default) and of port 8000 of the `pids` container (`8000` by default). On macOS, set `VIZ_PORT=5001`: port 5000 is used by AirPlay Receiver (or turn it off in **System Settings > General > AirDrop & Handoff**). |
| `COMPOSE_PROJECT_NAME` | *(optional)* Prefix of the `pids` container name, useful if several users share a machine. |

!!! warning
    Each time you modify `.env`, run `source .env` before running `docker compose` again.

## 3. Open the PIDSMaker container

All coding and experiments happen in the `pids` container. The repository is mounted at `/home/pids`, so code changes are seen without rebuilding the image.

=== ":material-microsoft-visual-studio-code: VS Code Dev Container (recommended)"

    Install the [Dev Containers](https://code.visualstudio.com/docs/devcontainers/create-dev-container) extension, then press ++ctrl+shift+p++ and run **Dev Containers: Open Folder in Container**.
    You get a full IDE inside the container, including the debugger.

=== ":lucide-terminal: Terminal"

    ```shell
    docker compose -f compose-pidsmaker.yml up -d --build
    docker compose exec pids bash
    ```

!!! note ":fontawesome-brands-apple: macOS, or Linux without an NVIDIA GPU"
    `up` fails with `could not select device driver "nvidia"`. Add the CPU override, which removes the GPU reservation (requires Docker Compose 2.24 or later, see `docker compose version`):

    ```shell
    docker compose -f compose-pidsmaker.yml -f compose-pidsmaker.cpu.yml up -d --build
    ```

    With VS Code, add `"../compose-pidsmaker.cpu.yml"` to `dockerComposeFile` in `.devcontainer/devcontainer.json`.

## 4. Download a dataset and run

From the `pids` container, [download datasets](installation.md#2-download-the-datasets) and run a first system:

```shell
pidsmaker download CADETS_E3
pidsmaker velox CADETS_E3
```

In the container, datasets are stored in `/home/artifacts/datasets/parquet/` (`PIDSMAKER_DATASETS_DIR`, set by `compose-pidsmaker.yml`), so they are kept in `ARTIFACTS_DIR` on the host when the container is recreated, and the outputs of runs in `/home/artifacts/`.

To log runs to Weights & Biases, run `wandb login` in the container (see [Log in to Weights & Biases](installation.md#3-log-in-to-weights-biases)). Continue with the [Quickstart](quickstart.md).
